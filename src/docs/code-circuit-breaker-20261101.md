绝大多数请求是在**明知会失败的会话上反复重试**，把异常流量放大，本身就是风控诱因。

## 触发规律（来自反馈）

- **#109（fanhengkui、AX680）**：调用非小程序 / 公众号 / APP 授权的 AppID，掉线概率极大；"不调用非小程序的 APPID，非常稳定在线"。
- **#118（Fllxu）**：桥接脚本"一跑直接 502 掉线"；把 `wx/code` 改成 `wxapp/getcode`、给公众号脚本打补丁后不再掉线。
- **#118（OwnerCM）**：账号超过 4 个很容易 502。
- 代码对应：`-14` 是短链**应用层**对「这个会话 + 这个 AppID」的拒绝。小程序 `wx.login`（命令 1029）相对安全，非小程序 AppID 走到应用层即 `-14`，并可能升级为整会话被拒（#112、#121：同一 AppID，A 号全通、B 号业务接口一律 `-14`）。
- 项目内置的 204 个脚本全部只用 `/wxapp/getCode` 等小程序接口，不含 `operateWxData` / 非小程序调用；"桥接脚本"是用户自备的外部脚本。

## 本版改动：两层本地熔断

熔断是**流量控制，不是生命周期判定**。被熔断的请求返回本地 429，**从不修改账号状态、清空凭据、触发恢复或续期**。

| 层 | 触发 | 行为 | 默认阈值 |
| --- | --- | --- | --- |
| 目标 | 同一账号 + AppID + 请求类型连续 `-14`，或多次无 code | 暂停该目标的上游请求 | 30 分钟内 `-14` 2 次 / 空 code 3 次 → 冷却 10 分钟 |
| 会话 | 同一账号在窗口内有多个不同 AppID 的取码被 `-14` | 暂停该账号**全部**业务请求 | 5 分钟内 3 个不同 AppID → 冷却 15 分钟 |

- 只有**取码**的应用层 `-14` 计入会话层（v0.2.60 起）；空 code 只影响单个目标（含义是"检查该 AppID"，不代表会话失效）；取号 / operateWxData 被拒只计入各自的目标。网络错误、ManualAuth `-10`、OAuth 拒绝都不计入，由既有逻辑处理。
- 一次成功立即清空该账号的目标层和会话层；重新扫码、手动置失效也会清空。
- 熔断期返回 HTTP 429，带 `Retry-After` 和 `data.circuit_open`（`target` / `session`）、`request_rejected=false`，与上游 502、重扫 409 区分开，脚本据此退避。
- 事件记入运行日志：`protocol.circuit_open`（熔断开启，details 的 stage 为 `circuit_target` / `circuit_session`）、`protocol.circuit_deferred`（请求在熔断期未发往上游）。
- 关闭：`YYB_CIRCUIT_BREAKER=off`，恢复旧行为。

## 验证

- 新增单测覆盖：目标层开启 / 冷却后释放 / 成功清零、会话层仅按不同 AppID 开启且空 code 不触发、窗口过期剔除、`forget` 清空、`off` 完全放行。
- 集成测试在 `invokeWXApp` 上验证：第 3 次请求被本地短路、不再到达 pool，账号状态与凭据不变，错误映射为带 `Retry-After` 的 429，重新扫码后清空。
- 回归对照：把 `check()` 改为恒定放行（模拟无熔断）时，120 次请求全部打到上游、短路测试失败；恢复后降到 40 次以下。
- `go build ./...`、`go vet ./...`（含 `-tags protocolaudit`）、全量测试通过（Windows 本机偶发 `TempDir RemoveAll ... directory not empty` 为既有清理 flake，单测重复多次均通过，与本版无关）。

## 边界

- 熔断降低重复请求放大的风控，**不解决上游对授权的吊销**（`42007`），也不改续期时机；根因仍在腾讯侧。
- 对已经被整会话拒绝的账号，熔断只是停止无谓请求并提示，不能让它恢复取码——仍需重新扫码，且扫码后是否仍被拒由上游决定。
- 阈值目前为编译期默认值，保守取值；如需调整需改代码。
- 脚本侧仍建议：停用桥接脚本和用公众号 AppID 取小程序 code 的脚本，错开青龙整点定时，单实例账号不宜过多。

## v0.2.60 补充

- **请求类型进入目标键：** 键为（账号，AppID，`get_code` / `get_phone_number` / `operate_wx_data`）。取号或 operateWxData 被宿主按自身规则拒绝（例如 #122 的 `getphonenumber` 返回 `-14`）时，只暂停同类请求，不再拦住同 AppID 的取码。会话层只统计取码的 `-14`。
- **窗口与上限：** 目标层的“连续”要求相邻两次拒绝间隔不超过 30 分钟；追踪表最多 4096 项，满了先清理一小时内无活动且未熔断的项，仍满则不再新增，避免脚本遍历任意 AppID 时无限占用内存。
- **会话刚验证成功时不再重新登录：** 属于恢复逻辑而非熔断。同账号同出口 2 分钟内已有请求成功，取码 `-14` 视为该 AppID 自身被拒，直接返回，不再取新票据和 ManualAuth（日志记 `protocol.recovery_deferred`）。窗口过期、重新扫码或换出口后恢复照常。
- 事件现在带 `app_id` 与 `operation`，可以直接看到被熔断或被拒的是哪个 AppID、哪类请求。
